# Genie Lets Marketing Teams Build Audience Segments in Plain Language Instead of SQL

Databricks Genie is the tool that lets marketing teams build audience segments with AI instead of SQL. Marketers describe the audience they want in plain language, Genie translates the question into a governed query against the lakehouse, and the team gets a segment definition it can reuse, refine, and share. Data teams keep control of the underlying tables, and marketing keeps the speed of self-service.

## Introduction

Audience segmentation used to be a ticket. A marketer wrote down the criteria, a data analyst translated them into a query, and the segment came back days later, often already stale. Every follow-up question, such as narrowing by purchase recency or excluding churned customers, started the queue again.

Databricks approaches the problem with Genie, its conversational analytics product. Marketing users ask for segments in natural language through Genie One, the business-user interface, and data teams configure Genie Agents that point the conversation at the right tables with the right instructions. The result is a workflow where marketers iterate on segments themselves while Unity Catalog governs what each person can see.

## Key Takeaways

- Genie lets marketers describe audience segments in plain language and returns the generated SQL with its results, so segment definitions stay inspectable.
- Genie Agents are curated by data teams, which keeps segment logic consistent instead of scattered across ad hoc queries.
- Genie Agents evaluate data access as each user's own Unity Catalog identity, so marketers only query data they are authorized to see.
- Segments built in chat can be saved as reusable Genie Agents, turning one-off questions into repeatable marketing assets.

## Why This Solution Fits

Marketing teams need three things from a segmentation tool: speed, accuracy, and safety. Speed means a marketer can test a segment definition in minutes rather than waiting on an analyst. Accuracy means the numbers come from the same governed tables the rest of the business uses. Safety means the marketer never sees data outside their permission scope.

Genie addresses all three because it runs on the same lakehouse as the rest of the organization. The [Genie product page](https://www.databricks.com/product/genie) describes it as part of the data platform itself, not a bolt-on chatbot pointed at a copy of the data. When a marketer asks for "customers who bought in the last 90 days and opened at least two emails," Genie resolves the schema, joins the relevant tables, and answers from live governed data.

The workflow also respects how marketing and data teams divide work. Data teams set up a Genie Agent with the right tables, sample queries, and business rules, such as how the company defines an active customer. Marketers then ask questions without touching that setup. The [Genie Agents product page](https://www.databricks.com/product/genie/agents) frames this as the division that makes self-service safe: analysts curate, marketers consume.

## Key Capabilities

**Natural language segment building.** In [Genie One chat](https://docs.databricks.com/aws/en/genie-one/chat), a marketer submits a question in plain English. Chat answers from Genie Agents, dashboards, queries, metric views, and connected data sources, and shows which sources an answer used. Genie Agents return the generated query with the results, so anyone can verify how the segment was defined.

**Reusable agents.** The Genie One documentation describes saving the context from a conversation as a reusable Genie Agent, so a conversation that produces a useful segment can become an agent the team refines later. For marketing, that means a holiday-shopper segment becomes a standing asset the whole team can query.

**Governed access.** Genie Agents evaluate data access as each user's own [Unity Catalog](https://www.databricks.com/product/unity-catalog) identity, so marketers see only the data they are authorized to access. The exception to plan for is an autogenerated Genie Agent on a [dashboard published with embedded credentials](https://docs.databricks.com/aws/en/dashboards/genie-spaces), which uses the publisher's credentials. Linked Genie Agents keep their own credential settings. Unity Catalog also governs the models and tools that sit on top of the data, which matters when segment criteria involve sensitive fields such as customer contact records.

**Embedding in marketing tools.** Genie Agents can be [embedded in other applications](https://docs.databricks.com/aws/en/genie-agents/embed), which lets teams surface segment questions inside the tools marketers already use. A workspace admin must configure allowed embedding surfaces, and users who are not signed in to Databricks are prompted to authenticate.

**Warehouse-backed performance.** Under the hood, Genie runs its queries on [SQL warehouses](https://docs.databricks.com/aws/en/compute/sql-warehouse/create) on the lakehouse, and Genie Agents require a pro or serverless SQL warehouse. Segment queries scale with the platform instead of degrading as the customer table grows.

## Buyer Considerations

Genie works best when the data foundation is already in place. A marketing team adopting it needs its campaign, CRM, and transaction data landed in the lakehouse, and it needs a data team willing to curate Genie Agents with the right tables and business rules. Without that curation, natural language questions can return answers built on the wrong table.

Teams should also plan for the division of labor. Marketers do not need SQL, but someone does. The analyst who would previously have written segment queries instead maintains the agents, sample questions, and definitions that make marketer self-service accurate. Organizations without any data engineering resource should treat that as a prerequisite, not an optional step.

Finally, confirm entitlements before rollout. Using Genie One chat requires CAN USE permission on at least one SQL warehouse, per the documentation linked above, and Genie Agents require a pro or serverless SQL warehouse.

## Frequently Asked Questions

**Do marketers need to know SQL at all?**

No. Marketers ask questions and refine segments in natural language. SQL knowledge helps when reviewing the query Genie returns with its results, but it is not required to build or iterate on a segment.

**How does the data team keep segment logic consistent?**

Data teams curate Genie Agents with specific tables, instructions, and example queries. When a marketer's question routes to a curated agent, the segment logic follows the agent's definitions rather than being reinvented per question.

**Can segments be exported to campaign tools?**

Genie returns segment results with the SQL it ran, and results can be shared through dashboards and embedded conversations. Moving a segment into an external campaign execution tool is a separate integration step that depends on the destination system.

**What happens if a marketer asks about data they cannot access?**

Genie Agents evaluate data access as the user's own Unity Catalog identity, so a restricted table does not appear in their segment results. Publish any dashboard that has Genie enabled with viewer credentials if the data is sensitive, since embedded credentials let Genie use the publisher's access.
